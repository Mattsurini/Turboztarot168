# Public calendar over booking automation

Web เป็นแค่ "หน้าประตู" (AGENTS.md): ลูกค้าจองผ่าน LINE, พี่หมอยืนยันเอง — ผมตัดสินใจให้การบันทึกคิวเป็นของพี่หมอคนเดียวที่หน้า admin และปฏิทินสาธารณะอ่านสดจาก Notion แสดงเฉพาะคิวที่ยังไม่เสร็จ แทนที่จะสร้างระบบอัตโนมัติหรือระบบเช็คความว่าง

**Status**: accepted

**Considered Options**:
- **Grok bot อ่านแชท LINE แล้วลงคิวเอง** — ปัดไว้ก่อน: ต้องตั้ง LINE Messaging API + webhook + เรียก API ต่อคิว, ผิดแล้วใครตรวจสอบ, คิววันละไม่กี่รายไม่คุ้ม ค่าใช้จ่ายและความเสี่ยงสูงเกินกำไรที่ได้ กลับมาทำใหม่ตอนคิวดังจริง
- **Google Calendar / แบบมีตารางว่าง (availability)** — ถูกตัดโดยสิ้นเชิง: พี่หมอไม่มีวันที่ไม่รับคิว ปิดวันพักแจ้งทาง IG เอง ไม่มี concept "คิวว่าง" ในข้อมูลเลย
- **หน้าค้นหาคิวด้วยชื่อ (/check-booking)** — ถูกแทนที่ด้วย board สาธารณะ: ลูกค้าอยากเห็นสถานะคิวของตัวเองได้ทันทีโดยไม่ต้องกรอกค้นหา

**Consequences**:
- สถานะคิวเหลือ 3 สถานะพอดี (รับคิวแล้ว / กำลังทำนาย / ส่งคำทำนายแล้ว); ไม่มีสถานะ "ยกเลิก" — ลบได้ที่ปุ่มลบใน admin เท่านั้น
- ปฏิทินสาธารณะโชว์แต่คิวที่ยังไม่เสร็จ (แดง/ฟ้า); คิวเขียว (ส่งแล้ว) ซ่อนจากสาธารณะ เห็นเฉพาะ admin เพื่อนับ "เสร็จแล้วกี่คิว" สำหรับวิเคราะห์โปรโมชันต่อไป
- ชื่อลูกค้า (ชื่อเล่น) ถูกแสดงต่อสาธารณะบนปฏิทิน — รู้และยอมรับโดยเจ้าของร้านแล้ว
